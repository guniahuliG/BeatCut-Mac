# BeatCut Studio — сборка приложений для Mac через GitHub

Проект создаёт две отдельные версии одного приложения с одинаковым интерфейсом:

| Файл результата | Для какого Mac | Минимальная macOS |
|---|---|---|
| BeatCut-Studio-Intel-Monterey.zip | Intel | 12.0, цель — Monterey 12.7.6 |
| BeatCut-Studio-Apple-Silicon.zip | M1/M2/M3/M4/M5 | 14.0, включая целевую Tahoe 26.3 |

Python, NumPy, SciPy, Tcl/Tk, FFmpeg и ffprobe включаются в `.app`. На компьютере пользователя их отдельно устанавливать не нужно. Файлы обрабатываются локально. Две сборки — это НЕ одно Universal-приложение.

**Статус:** проект сборки подготовлен, но сами macOS-сборки автором этого архива ещё не запускались. Исходный движок и интерфейс ранее тестировались на Linux. Успешная сборка и проверки в Actions не заменяют проверку запуска на реальном Monterey и M5/Tahoe. При первой сборке может потребоваться исправление конфигурации; точная ошибка будет в журнале.

## Через браузер — без терминала и без Python на вашем Mac

### 1. Создайте репозиторий

Войдите на github.com. Нажмите `+` вверху → `New repository`.

- Repository name: `BeatCut-Mac`.
- Для простого бесплатного старта выберите **Public**, если согласны открыть код другим людям. Видео, музыку, пароли и личные файлы туда НЕ загружайте. В этом проекте их нет.
- Включите `Add a README file`.
- Нажмите `Create repository`.

Public означает, что исходники и журналы сборки доступны всем. Если это не подходит, выберите Private и сначала проверьте лимиты Actions и расходы в настройках аккаунта. Бесплатность и доступность runners зависят от правил GitHub; платные возможности для этого проекта включать не требуется.

### 2. Загрузите проект

Распакуйте `BeatCut_Mac_GitHub.zip` на Mac. В репозитории нажмите `Add file` → `Upload files`.

Из распакованной папки перетащите в окно браузера **её содержимое**, а не ZIP и не внешнюю папку `BeatCut_Mac_GitHub`:

- папку `app`;
- папку `packaging`;
- `build-mac.yml`;
- `requirements-build.txt`;
- `README.md`;
- `THIRD_PARTY.md`;
- `LICENSE`.

Нажмите `Commit changes`. В корне репозитория должны быть видны папки `app` и `packaging`, не дополнительная внешняя папка.

### 3. Добавьте workflow

В архиве есть скрытая папка `.github` с готовым workflow. Finder обычно её не показывает, поэтому при загрузке через браузер проще создать этот файл явно:

1. В репозитории откройте **build-mac.yml**.
2. Нажмите кнопку **Copy raw file** в панели над кодом — скопируйте всё содержимое. Если кнопки нет, откройте `Raw` и скопируйте весь текст.
3. Вернитесь на вкладку `Code`.
4. `Add file` → `Create new file`.
5. В поле имени введите в точности:

```
.github/workflows/build-mac.yml
```

6. Вставьте скопированный текст без изменений и нажмите `Commit changes`.

Если этот файл уже был загружен вместе со скрытой папкой `.github`, создавать его второй раз не нужно. Если видите в Actions `Build BeatCut for Mac`, шаг выполнен.

### 4. Запустите сборку

1. Откройте вкладку **Actions**.
2. Если GitHub предлагает разрешить workflows для этого репозитория — разрешите, предварительно просмотрев workflow.
3. Слева выберите **Build BeatCut for Mac**.
4. Нажмите **Run workflow** → оставьте основную ветку → зелёную **Run workflow**.

Появятся две задачи: `Intel-Monterey` и `Apple-Silicon`. Каждая работает на своей архитектуре. Первая сборка FFmpeg из исходников может занять десятки минут; точного времени ожидания нет. В этой конфигурации предел задачи — 120 минут.

В вашем аккаунте сборка может потребовать подтверждения доступности Actions. Не вводите платёжные данные автоматически: сначала проверьте требования и лимиты GitHub.

### 5. Скачайте приложение

Когда задача закончится успешно, откройте страницу запуска и найдите внизу **Artifacts**:

- **BeatCut-Intel-Monterey** — для Intel с Monterey 12.7.6;
- **BeatCut-Apple-Silicon** — для M5 с Tahoe 26.3.

Для загрузки нужно быть авторизованным в GitHub. GitHub выдаёт ZIP-обёртку артефакта; внутри лежит ещё один ZIP приложения. Распакуйте внешний ZIP, затем внутренний. В итоге получите **BeatCut Studio.app**. Перенесите его в `Программы` и откройте.

Обе версии называются одинаково: не заменяйте приложение версией другой архитектуры. GitHub хранит артефакты этого workflow 14 дней, после чего может понадобиться повторная сборка.

Артефакты `Sources-*` и `Reports-*` не нужны для обычного запуска. Sources содержит исходники FFmpeg/x264 и проект; сохраните его, если собираетесь распространять приложение.

### 6. Первый запуск и проверка

Приложение имеет локальную ad-hoc подпись для целостности, но **не имеет подписи Developer ID и нотариализации Apple**. Это не идентифицированный разработчик. Gatekeeper может заблокировать первый запуск.

Если вы сами собрали приложение из этого репозитория и доверяете коду, используйте штатное разрешение macOS:

- Monterey: `Системные настройки` → `Защита и безопасность` → `Основные`, после попытки запуска проверьте доступность кнопки разрешения.
- Tahoe: `Системные настройки` → `Конфиденциальность и безопасность`, найдите сообщение о заблокированном приложении и доступное действие открытия.

Точный текст кнопок зависит от версии системы и её политики. Полностью отключать Gatekeeper, SIP или антивирус НЕ нужно. Если система пишет «повреждено» и обычного разрешения нет, не выполняйте случайные команды для обхода защиты: сначала проверьте сборку, ZIP и сообщение ошибки.

В приложении:
1. Откройте видео и аудио.
2. Выберите место сохранения нового MP4.
3. Выберите стиль `Клиповый`.
4. Для теста: `Быстрый тест 640×360`, длина `20` секунд.
5. Нажмите `Рендеринг`.
6. Проверьте изображение, звук, переходы и длительность на обоих Mac.

Встроенного предпросмотра пока нет: смотрите отрендеренный короткий тест. При сбое запуска журнал может быть создан в `~/Library/Logs/BeatCut Studio/startup-error.txt`.

## Если сборка красная

Откройте неудачный запуск → красную задачу → красный шаг. Скопируйте последнюю ошибку и примерно 20 строк перед ней или пришлите скриншот. Пароли, токены, коды подтверждения присылать не нужно.

Если сборка Intel остановилась на `Audit architecture...`, значит найден несовместимый компонент или внешняя зависимость. Не удаляйте проверку: её задача — не выдавать заведомо неподходящую для Monterey сборку.

Если сборка долго находится в `Queued`, возможна очередь GitHub или ограничение аккаунта. Доступность названий runner проверялась по документации при подготовке, но GitHub может изменить их.

## Что проверяется автоматически

- Архитектура машины сборки совпадает с целевой.
- SHA256 скачанного Python-инсталлятора и исходников FFmpeg/x264 совпадают с зафиксированными значениями.
- Модульные тесты планировщика монтажа.
- Каждая Mach-O библиотека содержит нужную архитектуру и не требует macOS новее заявленного минимума.
- Нет абсолютных ссылок на сторонние библиотеки из Homebrew или окружения сборки.
- Целостность подписи bundle.
- FFmpeg/ffprobe действительно берутся из `.app`, а не из системы.
- Внутри готового приложения собирается короткий тест для каждого из шести эффектов и обычной склейки; проверяются число кадров, длительность аудио и временные метки.

Это не проверяет все возможности GUI, работу Gatekeeper на машине пользователя, драйверы или совместимость с каждым видеоформатом. Intel-сборка создаётся на более новой macOS с целью 12.0; только реальный запуск на Monterey подтверждает практическую совместимость. Apple Silicon-сборка также требует проверки на M5/Tahoe.

## Что умеет монтаж

Случайные фрагменты, эвристический поиск низкочастотных акцентов, разная плотность склеек, короткие серии и длинные кадры. Обычные склейки смешиваются с наплывами, сдвигами, шторкой, круговым раскрытием и пикселизацией. Переход заканчивается на выбранном акценте, не сокращая музыку. Нет выделения кика нейросетью, распознавания дропов, speed ramp и смыслового анализа кадров. На музыке без чётких ударов возможны склейки по времени.

Настройки снимаются при нажатии «Рендеринг», между запусками приложения не сохраняются. Seed пустой — новый случайный вариант. Остановка во время анализа аудио может подождать окончания анализа. Рендер CPU; нужны время и свободное место.

## Технические заметки

- Native runners: `macos-15-intel` и `macos-15` (arm64).
- Python 3.12.10 с python.org выбран с Tcl/Tk и поддержкой старых macOS; это фиксированная версия, а не обещание самого свежего runtime.
- NumPy/SciPy устанавливаются из фиксированных wheel-версий. PyInstaller включает runtime, Python-модули и Tcl/Tk.
- FFmpeg 7.1.3 и x264 собираются из проверенных исходных архивов; отключено автообнаружение Homebrew-библиотек и сетевые протоколы FFmpeg.
- Автообновления приложения и его библиотек нет. Перед публичным распространением проверяйте обновления безопасности и повторяйте тесты.
- Первый этап может устанавливать pkgconf через Homebrew на CI-машине. На пользовательском Mac Homebrew не нужен.
- Никаких Apple Developer ключей, паролей или GitHub secrets текущий workflow не требует. Подпись Developer ID и нотариализация в него не включены.
